# 🤖 .agentignore — Agent Access Control

The `.agentignore` file acts as a barrier, preventing AI agents from interacting with, reading, or modifying specified paths within the Rotkeeper repository.

This file lives at the root of the repository:

```
.agentignore
```

---

## 🛠️ What It Does

1. **Restricts Access**: Defines paths that AI agents must completely ignore during automated sweeps, code generation, or analysis.
2. **Protects Artifacts**: Safeguards compiled output directories (like `bones/book-reports`) and private configurations from accidental overwrite by over-eager agents.

---

## 🔁 Behavior

- Agents reading this repository are expected to parse this file and exclude matched patterns from their internal file tree maps.
- It operates similarly to `.gitignore` but is strictly scoped to AI tools and agents.

---

## ⚠️ Notes & Caveats

- Ensuring agents actually respect this file relies on the agent's internal tooling respecting the `.agentignore` standard. It is a social contract, not a cryptographic lock.

### Architectural Intent
The `.agentignore` file establishes a strict boundary for AI agents operating within the Rotkeeper ecosystem. It explicitly prevents agents from accessing, reading, or modifying protected directories, such as compiled book reports (`bones/book-reports`) and other sensitive system paths. This ensures that autonomous operations do not inadvertently destroy human-crafted lore or break generated artifacts.

### Directory / File Schema Expectations
Located at the root of the repository (`.agentignore`), it utilizes a standard newline-delimited path format similar to `.gitignore`. AI agents are contractually obligated to parse this file and omit listed directories from their working context.

### Restless Spirits
This is a soft barrier. It relies entirely on the AI agent's tooling to honor the ignore list. A rogue or poorly configured agent could easily bypass this and obliterate protected files.

### Ritual Warnings
Never put critical security keys here expecting them to be safe; this only stops well-behaved scripts, not determined extraction.
