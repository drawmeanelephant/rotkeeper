### Design

DIP reads nonblank, noncomment entries as exclusions when they look like
paths or identify existing repository entries. It uses component-boundary
prefix matching for those paths in core discovery and obsolete-page checks.

### Limits

The current file contains only `v0.2.0`. DIP's dotted-entry test treats it
as a path-like exclusion, but no current source or documentation target
matches it. The file therefore excludes no existing paths.

### Cautions

This is DIP configuration, not a general write or deletion guard. Adding a
path can remove it from the core reference inventory as well as exempt its
documentation from obsolete handling.
